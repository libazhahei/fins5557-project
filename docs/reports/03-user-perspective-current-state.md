## 1. 一句话现状

你可以 **注册登录 → 点三个策略模板跑回测 → 在实验记录看摘要 → 在图表看 K 线与权益曲线 → 用对话（在配好模型时）触发同类模板**。  
你还 **不能** 像 PRD 承诺的那样：完整改假设对比、读成熟人话报告、编排流水线、看买卖点/再平衡叠加、或依赖稳定云端个人空间。

产品骨架已立；**研究闭环的「跑得通」强于「讲得清」**。

---

## 2. 用户能走通的路径

### 2.1 登录与进入

1. 打开 Web，进入登录/注册。  
2. 注册需邀请码（默认文档示例：`quant-lab-invite`，以 `.env` 为准）。  
3. 登录后进入 **实验室**（默认首页）。

感知：流程短，符合「轻量多用户」；没有复杂 onboarding。

### 2.2 模板回测（当前最稳的主路径）

实验室提供三个按钮：

| 模板 | 用户直觉 |
| --- | --- |
| 买入持有基准 | 最简单基准 |
| 经典 60/40 | 股债经典配比 |
| 趋势 + 波动目标 | 产品主打故事（DD-Guard 类） |

点击后系统会跑一轮（默认用 **离线行情 fixture**，不依赖外网 yfinance）。成功提示去「实验记录」或「图表」。

感知：入门者不用写代码就能「跑出一次结果」——接近旅程 A 的前半段。

### 2.3 实验记录

- 看到自己的 run 列表：名称、状态、模板、时间。  
- 摘要目前以 **JSON 指标块** 展示，而不是排版好的卡片 + 人话解读。

感知：有「我跑过什么」的记忆；但 **理解成本仍偏工程师**。

### 2.4 图表

- 取最近一次实验相关标的的 K 线。  
- 可切换标的；叠加 **权益曲线**。  
- 缺：完整买卖点、再平衡标记、regime 底色、与解读报告的深链。

感知：「有图了」，但离「图表讲故事」还有距离。

### 2.5 对话实验室

- 可选 Gemini / DeepSeek。  
- 发送自然语言；后端经 API 代理到 agent。  
- Agent 工具可列模板、跑模板、查 run；无 Key 时可能走规则回退（例如趋势模板相关请求）。

感知：对话存在，但体验依赖 Key 与 agent 是否在跑；失败时聊天区直接显示错误字符串，恢复路径不够友好。

### 2.6 流水线 / 设置

- **流水线**：静态列出 M1–M9，**不能拖拽/勾选组装**。  
- **设置**：展示当前模型配置 JSON，**不能**在 UI 里安全地填自己的 Key 或改默认标的池。

感知：导航齐全，进阶能力「看得见、摸不着」。

## 3. 对照 PRD 旅程的完成度

### 旅程 A — 入门者第一次成功

| 步骤 | 状态 | 用户感受 |
| --- | --- | --- |
| 邀请码注册登录 | 可用 | 顺畅 |
| 选模板或对话 | 模板稳；对话视环境 | 模板更值得推荐给新用户 |
| 确认参数摘要 | 弱 | 点按钮即跑，缺少显式「确认成本/区间」屏 |
| 进度可见 | 弱 | 同步跑完为主，缺少步骤 SSE 叙事 |
| 图表看点位 | 部分 | 有 K 线+权益，缺交易标注 |
| 读 LLM 解读 | 弱/未成形 | 结果偏原始摘要 |
| 改参数再对比 | 基本不可 | 无对比 UI、克隆 run |

**结论**：能完成「第一次跑出数字」，较难完成「15 分钟内理解并迭代」。

### 旅程 B — 研究者迭代

| 能力 | 状态 |
| --- | --- |
| 多资产假设对话 | 部分（工具面窄） |
| 图表查回撤段 regime | 不足 |
| 克隆改一参数 | 无 |
| 蒙特卡洛 | 模块存在，主路径未产品化 |

## 4. 信任与教学（用户最敏感的一层）

**已做到**

- 页脚固定研究免责声明。  
- 模板名中文、导航中文，降低陌生感。  
- 默认 fixture 降低「第一次就因行情 API 失败」的挫败。

**未做到 / 偏弱**

- 结果区缺少「成本假设、样本长度、是否可能过拟合」的固定诚实提示块。  
- 指标缺少首次出现的人话定义。  
- JSON 摘要强化了「这是给开发者看的 demo」印象，削弱研究台专业感。  
- 云端旧部署笔记仍提醒：冷启动、内存、工作区被清空——若用户仍访问旧 Cloud Run URL，会与本地 Lab 体验不一致，产生「产品不稳定」判断。

## 5. 用户分段建议（如何用现在这版）

| 你是谁 | 建议用法 | 暂勿期待 |
| --- | --- | --- |
| 课程/演示观众 | 本地起 api+web，点三个模板，对比实验记录数字，打开图表 | 云端持久账号、精美报告 |
| 量化入门自学 | 先模板，再尝试对话「帮我跑趋势+波动目标」；把 JSON 指标抄成笔记 | 无代码改假设对比 |
| 个人研究者 | 把 Lab 当编排雏形；重逻辑仍可对照 `packages/quant` / legacy RV | 生产级 Job 队列与 MC 产品流 |
| 产品/设计评审 | 用本报告 + IA 导航走查空状态与文案缺口 | 把流水线页当成已交付功能 |

## 6. 体验优先级（从用户痛苦排序）

1. **结果可读性**：摘要卡片 + 人话三段解读 + 诚实提示（比新功能更能提升「像产品」）。  
2. **参数确认与再跑**：跑前摘要；改一个旋钮生成新 run。  
3. **图表叙事**：买卖/再平衡叠加；从 run 深链进图表。  
4. **对话可靠性**：agent 未启动 / 无 Key 时的明确空状态与下一步。  
5. **对比与流水线**：研究者迭代与教学透明性。  
6. **云端持久**：只有在本地闭环满意后再强调，否则会放大运维创伤记忆。

---

## 7. 用户视角总结

Quant Lab 今天是一个 **可演示的 Agent-first 研究台骨架**：登录与模板回测建立了信任的第一块砖；图表与实验列表证明数据能留下来；对话与 M1–M9 暗示了完整故事。

但若以 PRD 的成功标准衡量——「能用自己的话复述规则与主要风险」「同会话两次对比」「结果从不黑箱」——当前版本仍处于 **MVP 中段**：工程师已看见架构，用户主要看见按钮与 JSON。

下一步对用户价值最大的，不是再增加导航项，而是把 **同一次回测讲清楚、改一处再跑、在图上对得上**。
