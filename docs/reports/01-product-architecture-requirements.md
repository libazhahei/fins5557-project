## 1. 产品定位与架构（业务层）

Quant Lab 不是交易终端，也不是纯 Notebook。它把「想法验证」拆成一条可复述的价值链：

```text
意图（对话/模板）
  → 假设固化（标的、规则、成本、区间）
  → 可组装研究步骤（数据→指标→组合→再平衡→回测→可选压力/ML→报告）
  → 可视化与解读
  → 实验留存与对比迭代
```

### 1.1 目标用户

| 人格 | 要完成的工作 | 主要痛点 |
| --- | --- | --- |
| 个人研究者 | 快速验证假设、留轨迹、对比 run | 工具散落、复现成本高 |
| 量化入门者 | 搞懂「想法→规则→回测→指标」 | 术语多、怕写代码、看不懂风险 |

**明确非目标（v1）**：实盘下单、高频 tick、机构多租户权限/SSO。

### 1.2 产品原则（设计约束）

1. **对话优先，面板辅助** — 默认进「实验室」；流水线是进阶视图。
2. **每步可见、可重跑** — 不黑箱；Job 有状态与输入输出。
3. **图表讲故事** — K 线与买卖/再平衡/权益联动，少堆无关联 KPI 卡。
4. **入门友好的诚实** — 必须暴露成本、区间、过拟合与「历史≠未来」。
5. **本地可玩、云上可部署** — 开发轻量；生产可迁 Cloud Run。

### 1.3 信息架构（用户心智模型）

| 导航 | 路由 | 用户感知的一句话 |
| --- | --- | --- |
| 实验室 | `/` | 说话或点模板，把想法变成回测 |
| 图表 | `/charts` | 看 K 线 + 权益，理解「钱怎么走的」 |
| 实验记录 | `/runs` | 历史实验与摘要，以后做对比 |
| 流水线 | `/pipeline` | 看清 M1–M9 拆了哪几步（进阶） |
| 设置 | `/settings` | 账号、模型、默认宇宙 |

品牌 **Quant Lab** 在壳层始终可见；实验室第一屏以对话 + 模板为主，不堆指标条。

## 2. 设计需求（体验与内容）

### 2.1 视觉与交互方向

- 气质：**研究工作台 / Data Dashboard**，克制、信息密度适中、单一强调色。
- UI 语言：**中文优先**；标的代码保留 `SPY` 等市场惯例。
- 免责声明固定在页脚：仅供研究，不构成投资建议。

### 2.2 文案与教学语气

- 指标首次出现给一句人话定义（如最大回撤）。
- Agent 回复结构：**结论 → 依据 → 可执行下一步**（按钮级行动）。
- **禁止**：保证收益、暗示实盘建议。

### 2.3 关键旅程（验收剧本）

**旅程 A — 入门者第一次成功（P0）**

1. 邀请码注册登录  
2. 选「趋势 + 波动目标」或对话描述  
3. 确认参数 → 运行  
4. 看图表买卖/权益 → 读解读  
5. 问「波动目标改成 8%」→ 新 run  

验收：无需写代码；约 15 分钟内完成首次回测+解读。

**旅程 B — 研究者迭代（P0/P1）**

多资产假设 → 图表查回撤段 → 克隆改一处再跑 →（P1）蒙特卡洛。

## 3. 功能与实现需求（产品语言 → 能力映射）

优先级：P0 闭环；P1 增强；P2 后置。

### 3.1 P0 — MVP 必须闭环

| 产品能力 | 用户语言 | 实现落点（模块/面） |
| --- | --- | --- |
| 账户隔离 | 邀请码注册、登录、只看自己的实验 | Auth JWT + `user_id` |
| 实验室对话 | 自然语言拆步骤并触发回测 | Agent + tools → API |
| 策略模板 | 买入持有 / 60·40 / 趋势+波动目标 / 空白 | `runs/from-template` |
| 数据与标的 | ETF 宇宙、区间与缓存对用户透明 | M1 `data.fetch` |
| 回测结果 | 收益/波动/回撤/夏普 + 基准感 | M5 + Run summary |
| 图表 K2 | K 线、权益联动；买卖点/再平衡（目标） | `/bars` + overlays |
| LLM 解读 | 做了什么、结果怎样、风险与下一步 | M9 `report.build` |
| 实验列表 | 看见历史 run | `/runs` |

### 3.2 P1 — Lab+

- 流水线可视化编排（与对话同一 Job 模型）
- Run 两两对比、克隆参数
- 蒙特卡洛压力（M6）
- RV/ML 进阶入口（M8，承接原 RV Prediction Pipeline）

### 3.3 P2 / Cloud

- 稳定托管、持久对象存储、用户自备 LLM Key 的完整 UX

### 3.4 明确不做（v1）

实盘/券商、WebSocket 行情、Level-2、无人值守「日赚 X%」、终端级画线与自定义指标脚本、复杂 SSO。

## 4. 与历史产品线的关系

仓库同时承载两代叙事：

1. **遗产**：`legacy/` / README 中的 **RV Prediction Pipeline**（波动率体制二分类教学流水线、Streamlit、Optuna 等）— 研究内核与课件资产。  
2. **现行产品**：**Quant Lab** — Agent-first 回测研究台；RV/ML 降为 P1 可插拔模块（M8），不再是唯一门面。

产品报告以 Quant Lab 为准；RV 能力作为「进阶实验」保留在路线图中。

## 5. 成功标准（产品）

| 指标 | 目标 |
| --- | --- |
| 首次成功回测 | 旅程 A 可独立完成 |
| 理解感 | 用户能复述「策略规则 + 一个主要风险」 |
| 迭代 | 同会话至少 2 次参数变更对比 |
| 信任 | 结果始终暴露成本/区间/基准；无「只给结论」 |

### 交付分期（产品语言）

| 阶段 | 用户得到什么 |
| --- | --- |
| MVP | 登录、模板/对话回测、K2、基础解读、实验列表 |
| Lab+ | 流水线可视、对比、MC、RV/ML |
| Cloud | 稳定托管、数据持久、自带 Key |

## 6. 产品视角下的当前缺口（相对 PRD）

实现细节见技术报告；产品侧主要缺口：

- 对话驱动的「改一参数再对比」体验未完成闭环（解读深度、对比 UI）。
- 图表尚未完整叠加买卖点/再平衡/regime（K2 目标态）。
- 流水线页仍是说明列表，不是可编排工作台。
- 设置页缺少自备 Key、默认标的池等完整控制。
- 诚实提示与「人话指标释义」在结果区仍偏原始（JSON 摘要为主）。

这些缺口决定了：产品愿景清晰，但 **MVP 验收剧本尚未全部可走通到 PRD 标准**。
